# Zorg MemoryDB v1.2.60

## Routine recall-QA repair documentation

This release documents the public-safe process for making recall repairs a
normal operating routine after an operator-reported process or rule miss.

## Changed

- Added a routine recall-QA repair loop to `docs/rules-and-recall.md`.
- Clarified that weak retrieval should strengthen the existing rule or memory
  instead of creating a duplicate rule when the existing source is still the
  correct authority.
- Documented the additive repair surfaces: recall hints, query observations,
  semantic edges, dynamic weights, materialized/search support, and regression
  queries.
- Updated the schema summary to connect those additive objects to exact-phrase
  verification and recall-view refreshes.

## Public safety

- This release contains process documentation only.
- It does not publish live database rows, private operator messages, query
  result payloads, contacts, credentials, backup dumps, or private transcripts.

## Verification

- Verified the live MemoryDB repair pattern locally before documenting it:
  representative process-recall phrases returned the strengthened existing
  exhaustive-memory/process rule at rank 1, and the related voice-checklist
  phrase returned the existing voice rule at rank 1.
- Ran the local MemoryDB speed test after the recall-surface refresh.
