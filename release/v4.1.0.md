# Zorg MemoryDB v4.1.0

Zorg MemoryDB v4.1.0 brings the current public-safe database, recall, agent
integration, and operator interfaces into one aligned release. It expands the
package beyond v4.0.1 with proactive repair, stronger runtime compatibility,
ANN/semantic maintenance, updated OpenClaw plugin/MCP routing, LAN Command Chat
corrections, and durable service packaging.

## Highlights

- **Automatic MemoryDB repair:** the packaged rules and tools treat PostgreSQL,
  scheduler firing, workers, ANN/vector coverage, semantic capture, plugin/MCP
  routing, and connected recall interfaces as one repairable system. Source
  memory remains additive and is never replaced by a fallback store.
- **Faster, more exact recall:** bounded and exact recall procedures, alias
  handling, preflight ordering, runtime compatibility, and scope deduplication
  are updated together.
- **ANN and semantic durability:** local provider defaults, vector auto-healing,
  Ollama synchronization, queue processing, and telemetry compatibility are
  included without publishing private embeddings or live database rows.
- **OpenClaw-native integration:** plugin and MCP TypeScript sources, built
  distributions, manifests, locks, and runtime verification are versioned as a
  single `4.1.0` unit.
- **LAN Command Chat:** updated routing, prompt compilation, container defaults,
  and package locks keep the browser chat connected to MemoryDB while remaining
  a separate surface from Neural Recall Activity.
- **Neural Recall Activity:** the public production browser assets and
  documentation remain available. The retired `package/zorg/memory-3d/`
  package, production-host server, database environment, and credentials are
  deliberately excluded.
- **Service durability:** the PostgreSQL-owned LLM dispatcher unit is packaged,
  and the installer now fails clearly when required schema, trigger, plugin, or
  service activation is incomplete.

## Public-safety boundary

This release contains public-safe code, schema, reusable structural rules,
documentation, screenshots, and build artifacts only. It contains no database
dumps or private rows, contacts, messages, credentials, tokens, private
infrastructure, operator context, generated personal images, news audio, local
environment files, caches, or installation-specific state.

## Verification boundary

The release publisher is the working source system, so it was not used for
clean-install, reinstall, or upgrade testing. Verification on the source system
is limited to non-installing builds, syntax/static checks, public-safety scans,
version and source/distribution parity, package/archive integrity, and remote
GitHub release verification. Clean-install and existing-install upgrade testing
is delegated to another OpenClaw agent on a genuine target environment and must
be reported as separate evidence.
