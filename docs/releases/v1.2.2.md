# Zorg MemoryDB v1.2.2

Released: 2026-05-07

## Summary

This documentation release improves the public communication layer around Zorg MemoryDB. It adds a rule that public-facing messages should draw on truthful, public-safe lived operational examples when relevant, while avoiding mechanical setup language that announces the writing technique before making the point.

## Added

- Public communication guidance for searching durable memory before outside-facing communication to find relevant public-safe operational examples.
- Guidance to weave those examples naturally into emails, posts, pitches, and sales/positioning messages instead of saying things like "here is a personal example" or "speaking from experience."
- Explicit reminder that private recipient/operator context may guide tone silently, but must not be exposed.
- Template rules so fresh installs inherit the same public-communication discipline.

## Why it matters

Zorg MemoryDB is not only a factual recall system. It also gives an assistant enough continuity to communicate like someone who has done real work: recovering context, fixing publishing loops, verifying backups, remembering contact rules, and learning from mistakes. Public communication should use that history carefully and naturally, not as a feature dump or a visible checklist.

## Public/private boundary

This release adds only public-safe communication guidance. It does not publish private memories, transcripts, contacts, emails, credentials, operator strategy, or live database rows.
