# v1.1.0 — Production packaging and self-contained container release

This release turns `Zorg_MemoryDB` into a more professional production-style GitHub project with standard install docs, Docker/Dockge containment, GitHub Actions verification, GitHub Releases, and GitHub Container Registry publishing.

## Highlights

- Preserves the standard Ubuntu Linux install path.
- Adds Docker run / GHCR package install path.
- Keeps Docker Compose and Dockge installs self-contained.
- Runs OpenClaw and PostgreSQL inside one OpenClaw/Zorg container for Docker/Dockge.
- Adds CI checks for shell, Python, Docker Compose, and Docker build.
- Adds release automation for GitHub Releases and GHCR images.
- Adds production repository files: license, security policy, support, contributing guide, changelog, and release process docs.

## Install paths

Supported install paths now documented and maintained:

1. standard Ubuntu Linux install
2. Docker Compose install
3. Dockge install
4. Docker run one-liner using GHCR

## Compatibility

Docker/Dockge users should use the new single-container layout. Older two-container `openclaw` + `postgres` Compose installs should be replaced with the current stack after backing up any local data that matters.

## Verification

Verified locally before release:

- shell syntax validation
- Python compile validation
- Docker Compose config validation
- Docker build
- fresh self-contained Compose startup on alternate port `19892`
- embedded PostgreSQL ready on `127.0.0.1:5432`
- memory table listing succeeds
- recall router returns `database-direct-structured`

## Sanitization

The repository remains a sanitized template. It does not include private database rows, account data, emails, chats, transcripts, contacts, cookies, OAuth material, SSH keys, or operator context.
