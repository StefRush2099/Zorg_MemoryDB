# v1.2.0 - Living Memory Operations

Zorg MemoryDB v1.2.0 updates the public package to reflect the current design: DB-only durable memory, structured operating rules, automatic recall repair, rich communication defaults, recovery-first database handling, and better public explanation of why this exists on top of plain OpenClaw.

## Highlights

- **DB-only durable memory** — retired `memory/` markdown fallback is now archived into PostgreSQL and removed instead of being used as an active memory surface.
- **Automatic DB-only recall auto-heal** — added a checker that detects recreated retired memory files or fallback routes, archives/imports them into DB, removes the filesystem copy, refreshes recall surfaces, and stays silent unless blocked.
- **Structured logic rules** — core operating rules are promoted into `zorg_logic_rules` so recall can surface rules before broad memory text.
- **Rich-text email default** — outbound email helpers now generate HTML with a plain-text fallback by default for professional communication quality.
- **Database backup and tuning gate** — production DB/index/schema changes now require a verified local + private GitHub/off-host backup first and are gated by real recall failures.
- **Private GitHub recovery recommendation** — fresh installs should recommend a private GitHub recovery store when none exists because private repos are free and off-host DB recovery matters.
- **Release/documentation maintenance rule** — docs and releases must be updated when the MemoryDB design changes so users can see what is current.

- Removed active `memory/*.md` mapping from generated SQL memory maps.
- Updated recall/search schema so structured logic rules can participate in search and rank before broad memory hits.
- Updated `docs/why-zorg-memorydb.md` to explain the current difference from plain OpenClaw.
- Expanded database recovery docs around local backups, private GitHub recovery stores, and public/private repo boundaries.
- Updated templates so new installs inherit DB-only memory, auto-heal, recovery, tuning, and documentation-maintenance rules.

## Compatibility notes

- Public repo remains sanitized. It does **not** include private memory rows, DB dumps, contacts, emails, transcripts, credentials, or operator context.
- Private database backups should be stored only in local/private recovery locations, not in this public repo.
- Existing installs should run migration/upgrade helpers only after backing up their database.

## Reminder

Zorg MemoryDB is an additive OpenClaw memory layer. OpenClaw supplies the agent runtime; Zorg MemoryDB supplies the operating memory spine, structured rules, recovery discipline, and recall improvement path.

## Absolute Priority 0: Exhaustive Memory Before Response

The operator does not ask for work in context unless the needed information, access path, rule, contact, precedent, or working solution likely already exists somewhere in durable memory, project history, live configuration, runbooks, prompts, cron jobs, or related system state. A fast or shallow miss is never evidence of absence.

Before replying, asking a question, claiming uncertainty, or reporting a blocker, the assistant must scour the backend memory system deeply and creatively: use broader queries, alternate names, relationship terms, adjacent projects, prior similar tasks, contact records, operational history, runbooks, cron payloads, and live configuration clues until the relevant context is found or genuinely exhausted. Immediate answers are disallowed when memory could contain the answer.

If deep scouring finds information that the first query missed, treat that as a recall-structure failure and immediately add additive retrieval support: aliases, recall hints, semantic/relationship edges, query observations, indexes, materialized/search support, or rule surfaces so the same phrasing is fast and reliable next time. Preserve all source data; improve recall additively only.

Failure reports must not excuse the miss as “not enough information” when the information existed in memory. The correct diagnosis is inadequate recall behavior or structure, and the corrective action is deeper recall plus indexing/hinting/relationship repair.
