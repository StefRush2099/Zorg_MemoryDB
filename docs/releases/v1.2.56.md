# Zorg MemoryDB v1.2.56

## Canonical rule and backup guidance supersession

This release carries the current public-safe MemoryDB rule structure into the
repository so fresh installs and upgrades no longer inherit older backup or
legacy-rule guidance.

## Changed

- Active rule handling remains canonical in `public.zorg_logic_rules`.
- Older compatibility surfaces, including `public.zorg_rules` and
  `public.zorg_rule_catalog`, remain schema-compatible but are disabled as
  active rule-recall sources by the public canonical update SQL.
- Existing operator-visible chat timing rules are raised through
  `zorg_logic_rule_dynamic_weights`; no replacement timing rules are created.
- Database structural-change rollback now documents a verified temporary local
  PostgreSQL backup only.
- Public `Zorg_MemoryDB` update paths must not commit, mirror, or push live DB
  dumps, rows, contacts, transcripts, credentials, or private memory to GitHub.

## Verification

- Rechecked DB-backed memory connectivity and recall benchmark health before
  publishing.
- Searched current docs, templates, and schema seed text for stale
  private-GitHub backup requirements and replaced them with the current
  temporary-local-only rollback rule.
- Kept the update public-safe: no private database rows, dumps, transcripts,
  contacts, credentials, account data, emails, or operator-private context.
