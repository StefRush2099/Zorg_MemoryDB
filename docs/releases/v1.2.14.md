# Zorg MemoryDB v1.2.14

## Summary

This release catches up the public package after the rule, recall, LAN console, recovery, and verification hardening work that landed after `v1.2.11`. It keeps the public repository aligned with the current DB-only MemoryDB design without publishing private memory contents.

## Added

Added the Base Install Permanent Engineering Rules as public-safe schema and documentation so clean installs inherit exact-scope, real-source, verification, publication, screenshot, recall-durability, and overlay-safe upgrade requirements.

Added dynamic trigger backpressure documentation and schema for recall-adjacent queues that enqueue bounded work and adapt batch sizes/delays from observed backlog, runtime, and query timing.

Added public-safe system-change publication, screenshot-delivery, rule-failure lockout, and non-destructive recall-index tuning rules.

Added the master recovery rules contract template and self-recovery documentation for restoring the DB-backed memory path without publishing private backup data.

Added external DNS public URL verification guidance using Google DNS `8.8.8.8` where available.

Added current public LAN console screenshot assets for desktop light/dark documentation.

## Changed

Raised the semantic worker default cap from 12 to 64 jobs per batch after backlog audit evidence showed thousands of due queued jobs with no worker errors.

Hardened DB memory-search workspace resolution so OpenClaw launches from a home-directory working directory still find the workspace `.venv-sqlmem` and recall router.

Updated the bundled LAN command console WebSocket client for OpenClaw Gateway protocol v4 compatibility.

Promoted the LAN command console across the packaged Docker image, Docker Compose/Dockge stack, and native Ubuntu installer.

Removed retired `memory/` markdown files from the public repo/templates so clean installs do not recreate flat-file memory surfaces.

Clarified public-safe completed-work posting rules and canonical Hyperdine article links using `https://www.hyperdine.com/...`.

## Verification

Confirmed repository state was clean and synchronized with `origin/main` before release maintenance.

Reviewed structured DB recall rules and recent commits from `v1.2.11` through `HEAD`.

Ran shell syntax checks for repository shell scripts and the Docker entrypoint.

Ran Python bytecode compilation for repository Python scripts.

Validated Docker Compose configuration.

## Privacy

This release publishes only public-safe structure, rules, scripts, templates, schema, release notes, and documentation. It does not include private memory rows, database dumps, contacts, emails, transcripts, credentials, live account data, internal hosts, or operator-specific context.
