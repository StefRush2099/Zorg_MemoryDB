# Zorg MemoryDB v1.2.45

This release adds public-safe tail-latency tuning for DB recall while preserving all source memory.

## Changes

Added db/recall_tail_latency_cache_2026_05_21.sql.

Added zorg_logic_rules_fast_mv, a materialized active-rule recall surface with FTS, trigram, and weight indexes.

Wrapped zorg_recall_context with a neural-query-result cache so repeated recall queries can return from indexed prior results and fall back to full uncached recall on a cache miss.

Kept the previous full recall path as zorg_recall_context_uncached.

## Measured Local Result

On the live OpenClaw workspace after backup:

Before dynamic benchmark: p50 7.344 ms, p95 949.363 ms, max 1161.121 ms, total 21677.447 ms.

After dynamic benchmark: p50 3.471 ms, p95 51.275 ms, max 83.180 ms, total 1277.446 ms.

After canonical wrapper benchmark: p50 3.001 ms, p95 39.295 ms, max 52.875 ms, total 725.957 ms.

The performance gain came from avoiding repeated full scoring and write-heavy recall recomputation for queries that already have active neural result rows, plus precomputing active logic-rule recall text in an indexed materialized view.
