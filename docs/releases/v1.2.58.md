# Zorg MemoryDB v1.2.58

## DB-only runtime memory writer enforcement

This release carries the DB-only memory structural rules into the public-safe
repository so clean installs, upgrades, and repaired systems do not recreate
retired markdown memory files.

## Changed

- Added `db/runtime_db_only_memory_writer_rules_2026_06_04.sql` to seed the
  public-safe rules for DB-before-visible-response, DB-only runtime memory
  writers, and real timestamp/duration handling on visible operational replies.
- Updated `scripts/enforce_db_memory_search.py` so it also patches runtime
  writer surfaces: bundled `session-memory` markdown output is disabled and
  pre-compaction `memoryFlush` does not create `memory/YYYY-MM-DD.md` on
  DB-only installs.
- Extended `scripts/archive_retired_memory_dir.py` with direct-file import
  options so runtime-created memory artifacts can be imported into PostgreSQL
  and removed after successful import.
- Updated templates and rule documentation to state that permission-denied
  directories are not the enforcement mechanism; runtime writers must not
  create retired files, and any file that appears is emergency DB-import input.
- Added the user-visible timestamp/duration rule to the public-safe rule
  surfaces.

## Verification

- Syntax-checked the changed Python scripts.
- Applied the public-safe runtime rule SQL against the local PostgreSQL-backed
  memory database.
- Verified DB-backed recall can retrieve the runtime DB-only writer rule.
