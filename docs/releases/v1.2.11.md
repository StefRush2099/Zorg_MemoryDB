# Zorg MemoryDB v1.2.11

## Summary

This release adds a built-in LAN/local command chat to the base Zorg MemoryDB install, publishes the public-safe rationale for local-first agent communication, and advances the recall design with queue-driven semantic association support. It also documents recall-failure benchmarking and role-specialized AI DJ reporting patterns without publishing private memory contents.

## Added

- Added `lan-chat` as a built-in LAN web console and local command chat/back channel for OpenClaw/Zorg MemoryDB installs.
- Added Docker Compose wiring for the LAN console alongside the main OpenClaw service.
- Added LAN console documentation explaining why sensitive prompts and local agent coordination should have a LAN/private path instead of depending only on outside chat providers.
- Added queue-driven semantic neural recall v1 structures:
  - `db/semantic_neural_recall_v1.sql`
  - `memory_semantic_work_queue`
  - `memory_semantic_tuner_versions`
  - `memory_enqueue_semantic_job(...)`
  - `scripts/memory_semantic_worker.py`
- Added public-safe recall failure benchmark methodology and chart asset.
- Added an AI DJ agent reporting pattern for memory-backed persona, artist research, music-news, and streaming-station reporting.
- Added public-safe individual communication profile guidance.

## Changed

- Clarified that the LAN console is base communication infrastructure, not a separate optional side app.
- Updated README and setup docs to mention the LAN console and local-first privacy boundary.
- Updated schema and weighted-semantic-recall docs to describe the semantic queue/worker loop as an additive, source-preserving layer for nodes, weighted edges, recall hints, and query observations.
- Updated public operating-rule docs to keep communication, recall, and release-maintenance guidance aligned with the current design.

## Verification

## Privacy

This release publishes only public-safe structure, install behavior, scripts, templates, and documentation. It does not include private memory rows, database dumps, contacts, emails, transcripts, credentials, live account data, internal hosts, or operator-specific context.
