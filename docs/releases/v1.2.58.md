# Zorg MemoryDB v1.2.58

## Canonical public rule update

This release adds a public-safe SQL update for installs that need current
canonical rule handling without publishing private runtime data.

## Changed

- Added `db/public_canonical_rules_update_2026_06_02.sql`.
- The update seeds sanitized public rules into `zorg_logic_rules`.
- The update disables active rows in the older `zorg_rules` and
  `zorg_rule_catalog` compatibility tables.
- The update raises existing operator-visible chat timing dynamic weights
  through `zorg_logic_rule_dynamic_weights` without creating replacement timing
  rules.
- Updated rule/recall and schema docs so active rule recall is documented as
  canonical `zorg_logic_rules` plus dynamic weights.

## Compatibility

Existing installs can apply the SQL file as an additive upgrade. The legacy
compatibility tables may remain in the schema, but they should not remain active
rule-recall sources after canonical migration.

## Verification

- Queried DB-backed publication and rule-update requirements before editing.
- Rechecked current OpenClaw install, updating, and Docker documentation before
  documenting this as a SQL-only MemoryDB update rather than a replacement
  OpenClaw install.
- Kept the update public-safe: no private database rows, dumps, transcripts,
  contacts, credentials, account data, emails, or operator-private context.
- Validated the SQL file with PostgreSQL syntax parsing.
