# Zorg MemoryDB v1.2.12

## Summary

This release hardens DB-only memory recall startup when OpenClaw launches from a home-directory working directory instead of the workspace.

## Fixed

- Updated the DB memory-search runtime enforcer so the injected JavaScript helper resolves the workspace from `OPENCLAW_WORKSPACE`, then `$HOME/.openclaw/workspace`, and only falls back to `process.cwd()` when no home directory is available.
- This prevents the live `memory_search` tool from looking for `.venv-sqlmem` and `memory_recall_router.py` under the wrong current working directory.

## Verification

- Ran Python bytecode compilation for `scripts/enforce_db_memory_search.py`.
- Ran Node syntax validation on the patched live OpenClaw runtime bundle.
- Verified the real OpenClaw `memory_search` tool returns `database-direct-structured` results from PostgreSQL.

## Privacy

This release publishes only public-safe recall routing structure and documentation. It does not include private memory rows, database dumps, contacts, emails, transcripts, credentials, live account data, internal hosts, or operator-specific context.
