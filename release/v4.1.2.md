# Zorg MemoryDB v4.1.2

This patch release publishes the recovered fail-closed MemoryDB connector and the procedures required to install or recover it without outside intervention.

## Highlights

- Adds the working OpenClaw `agent_turn_prepare`/input gate to the public plugin source.
- Binds each turn to a PostgreSQL receipt containing run ID, session key, request hash, recall layers, result count, timing, and recovery incident.
- Holds the original request during a database fault; ordinary tools and outbound replies remain blocked.
- Allows one bounded database-down alert and one verified restoration alert while suppressing duplicates.
- Performs fresh recall after restoration and never reuses a stale receipt.
- Adds installation, recovery, rollback, and isolated connector acceptance runbooks.
- Replaces stale skill guidance that could recreate delegated task executors or parallel durable-memory paths.
- Carries the additive recall-cache, cognitive-memory, ANN repair, privacy, performance, and gauge verification work accumulated since v4.1.1.

## Upgrade safety

PostgreSQL remains the only durable memory and rule store. This release does not delete source memories, history, events, contradictions, embeddings, or provenance. Create and verify a logical backup before upgrade, stage the pinned package, apply additive migrations, validate runtime plugin registration, and run the complete acceptance matrix before reopening delivery.

The application database role is not assumed to own database objects. DDL requiring ownership must be performed by the owning role; MAINTAIN does not grant ownership.

## Verification

The release is accepted only when:

- plugin build and tests pass;
- healthy, slow, failed, restored, missing-receipt, and stale-receipt behavior passes;
- the full 13-gate MemoryDB suite passes;
- critical recall ranks first and exact/HNSW quality is unchanged;
- queues and indexes are healthy;
- source preservation and public/private isolation pass;
- root, plugin/MCP, packaged/live LAN package and lock versions all equal `4.1.2`;
- the compiled and authenticated LAN gauge displays `v4.1.2`;
- the public archive, remote commit, tag, release, asset, and rendered pages are verified.
