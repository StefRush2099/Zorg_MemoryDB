# Zorg MemoryDB v3.0.6

## Scope

This release completes the local plugin/MCP path for the existing PostgreSQL
Zorg MemoryDB backend. It does not modify or replace the backend database.

## Changes

- Advances the package, LAN Command Chat gauge metadata, OpenClaw plugin
  manifest, and MCP server to `3.0.6`.
- Adds the `memory_ann_status` tool for read-only visibility into active
  embeddings, queued and failed semantic work, and cached query embeddings.
- Adds the `memory_recall_preflight` tool so callers can invoke the canonical
  MemoryDB search path before ordinary recall.
- Resolves `SQL_MEMORY_MAP`/`ZORG_SQL_MEMORY_MAP` relative to
  `OPENCLAW_WORKSPACE`/`WORKSPACE_DIR`, keeping the plugin portable across
  installs.
- Rebuilds and validates the distributed plugin artifacts.
- Removes the legacy installer path that created or imported Markdown rule and
  memory files. Clean installs now initialize PostgreSQL and the native
  `zorg-memorydb` plugin/MCP without a Markdown fallback.

## Installation and update requirements

Remove the prior Zorg MemoryDB plugin package files before installing this
release; do not mix old and new plugin files. Keep the PostgreSQL backend and
its data in place. Install the package dependencies, configure the local SQL
memory map through the documented environment variables, build/validate the
plugin, and verify PostgreSQL health before enabling it.

After a successful update, the installing agent must announce in its clear
channel: `I have just updated the Zorg MemoryDB plugin/MCP to v3.0.6.`
