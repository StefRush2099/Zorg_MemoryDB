# Zorg MemoryDB v1.2.10

## Summary

This release hardens clean installs so Zorg MemoryDB keeps DB-only memory behavior from first boot and does not revert to durable markdown `memory/` files. It also documents Docker Compose access to the OpenClaw TUI/chat helper service.

## Added

- Added clean-install DB-only memory settings in Docker and standard Ubuntu install paths.
- Added an optional `openclaw-cli` Docker Compose helper service for launching OpenClaw TUI/chat against the same folder-local `./openclaw-home` state.
- Documented Docker Compose TUI/chat commands:
  - `docker compose run --rm openclaw-cli tui --local`
  - `docker compose run --rm openclaw-cli chat`

## Changed

- `scripts/enforce_db_memory_search.py` now creates or patches `openclaw.json` even when the file does not already exist, and removes unsupported stale `zorgMemoryDb` draft config keys.
- Docker and standard Ubuntu startup now write `agents.defaults.memorySearch` with DB-only settings: `enabled: true`, `provider: local`, `fallback: none`, `sources: [memory]`.
- Strengthened core/template rules to prohibit durable `memory/` markdown files and require DB repair/restore instead of markdown fallback.
- Made `scripts/db_only_memory_autoheal.py` honor `OPENCLAW_WORKSPACE`, `SQL_MEMORY_MAP`, and `SQLMEM_PYTHON` so clean installs and non-default workspaces can self-heal correctly, avoid startup-time materialized-view refreshes unless explicitly requested, and preserve the SQL venv Python path instead of resolving it to the system interpreter.
- First-run bootstrap now invokes DB-only auto-heal after importing core rules and enforcing memory routing; startup continues after logging any retryable auto-heal warning.

## Verification

- `python3 -m py_compile` passed for DB enforcement/auto-heal scripts.
- `bash -n` passed for Docker entrypoint, standard Ubuntu installer, and first-run script.
- `scripts/enforce_db_memory_search.py` created a fresh temp `openclaw.json` with DB-only memory settings.
- `docker compose --profile cli config` validated the Compose file and `openclaw-cli` service.
- Built and started a clean Docker Compose verification project, then verified both OpenClaw config paths contained DB-only memory settings and that `/home/openclaw/.openclaw/workspace/memory` was absent.

## Privacy

This release publishes only public-safe structure, install behavior, scripts, templates, and documentation. It does not include private memory rows, database dumps, contacts, emails, transcripts, credentials, live account data, internal hosts, or operator context.
