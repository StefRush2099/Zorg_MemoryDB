# Zorg MemoryDB v1.2.7

## Summary

This release fixes Docker Compose and Dockge folder-local install behavior so multiple installs on the same Docker host can live in separate folders without sharing a hard-coded project name or global OpenClaw data volume.

## Changed

- Removed the hard-coded top-level Docker Compose project `name`.
- Removed the hard-coded `COMPOSE_PROJECT_NAME=zorg_memorydb` default from `.env.example`.
- Replaced the global `zorg_openclaw_home` named volume with a folder-local `./openclaw-home:/home/openclaw/.openclaw` bind mount.
- Updated Docker, Dockge, and quickstart docs so installs can use any folder name and keep generated runtime state underneath that folder.
- Documented that multiple simultaneous installs need separate folders and unique gateway ports.

## Verification

- Docker Compose configuration validates with the folder-local bind mount.
- Test installs in separate folders confirmed Compose resolves each install to its own local `openclaw-home` path.
- Docker Compose build path verified from isolated install folders.

## Privacy

This release publishes only public-safe installer, Compose, and documentation changes. It does not include private memory rows, database dumps, contacts, emails, transcripts, credentials, live account data, internal hosts, or operator context.
