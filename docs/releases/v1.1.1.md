# v1.1.1 — Dockge lowercase folder confinement fix

This release fixes the remaining Dockge folder-confinement problem Stefan found. Dockge and Docker Compose normalize stack/project names to lowercase, so an uppercase clone/import path like `/opt/stacks/Zorg_MemoryDB` can result in Dockge creating a second lowercase folder such as `/opt/stacks/zorg_memorydb`.

## Fixed

- Canonical Dockge folder is now `/opt/stacks/zorg_memorydb`.
- Canonical Dockge stack name is now `zorg_memorydb`.
- `.env.example` now includes `COMPOSE_PROJECT_NAME=zorg_memorydb`.
- `docker-compose.yml` now declares `name: ${COMPOSE_PROJECT_NAME:-zorg_memorydb}`.
- Dockge docs now warn against uppercase Dockge folders and include migration guidance for duplicate uppercase/lowercase installs.

## Compatibility

Standard Ubuntu, Docker Compose, Docker run/GHCR, and Dockge install paths remain supported. Docker/Dockge still run OpenClaw and PostgreSQL inside one self-contained OpenClaw/Zorg container.
